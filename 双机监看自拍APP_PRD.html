双机监看自拍 APP · 产品需求文档

版本：v1.1 文档类型：PRD 日期：2026-10-26

v1.1 变更说明

  • 连接方式：仅保留 WiFi Direct 直连，删除局域网模式
  • 核心架构：改为屏幕共享 + 触摸控制方案，不再自研摄像头采集与独立反向控制 UI
  • 拍摄逻辑：用户在拍摄端打开原生相机 APP，监看端镜像并直接操作

  • 平台：仅 Android；不传音频，不传大文件

1. 背景与目标

1.1 场景问题

使用手机后置摄像头自拍时，拍摄者无法看到画面，导致构图、表情、对焦均不可控。常见的解决方案（镜面、远程快门、定时拍摄）均无法提供实时反馈，拍摄成功率低。

1.2 目标用户

  • 需要高质量后置自拍的个人用户（旅行、证件照、穿搭记录等）
  • 缺少专业相机监看设备的小型内容创作者
  • 希望用现有手机替代昂贵监看器的用户

1.3 产品目标

让用户仅用两台 Android 手机，通过 WiFi Direct 直连，将拍摄端的整个屏幕实时镜像到监看端，并由监看端直接触摸控制拍摄端，从而在监看端操作拍摄端的原生相机 APP，获得「所见即所拍」的后置自拍体验。

核心价值：把第二台手机变成拍摄手机的「无线触屏监视器」，复用原生相机全部功能（含美颜、专业模式、夜景等），零额外硬件。

2. 产品决策：核心架构与连接方式

2.1 核心架构决策：屏幕共享 + 触摸控制

传统思路是自研摄像头采集 + 推流 + 独立控制 UI，但这意味着要重新实现相机的所有功能（美颜、对焦、变焦、专业参数等），开发量大且体验不如原生相机。

产品决策
采用「屏幕镜像 + 触摸转发」方案，复用拍摄端原生相机 APP。

监看端实时显示拍摄端的整个屏幕，并将触摸操作转发到拍摄端。用户在拍摄端打开原生相机 APP，即可在监看端完成取景、对焦、变焦、拍照、录像、美颜调节等全部操作。无需自研相机功能。

✓ 屏幕共享方案（采用）

  • 复用原生相机全部功能（美颜、专业模式、夜景…）
  • 无需自研摄像头采集与控制 UI
  • 触摸即控制，操作直觉与本机一致
  • 开发量小，可基于开源 scrcpy 协议
  • 限制：需拍摄端开启「无线调试」

✗ 自研采集方案（不采用）

  • 需重新实现相机全部功能
  • 美颜、对焦、变焦等需逐一适配
  • 开发量大，体验难超越原生相机
  • 仅在需要极低延迟或特殊效果时考虑

2.2 连接方式决策：仅 WiFi Direct 直连

产品决策
MVP 仅支持 WiFi Direct 直连，不做局域网模式。

WiFi Direct 让两台设备直接建立点对点连接，不经过路由器，延迟更低、更稳定，且不依赖外部 WiFi 环境。监看端在连接期间会断开原有 WiFi。

2.3 Type-C 有线方案评估（P1 备选）

2.3.1 纯 Type-C 线传摄像头画面（不用采集卡）

维度结论
是否可行有条件可行
技术路径拍摄端启用 Android 原生 DeviceAsWebcam（UVC Gadget），通过 Type-C 以 UVC 协议输出摄像头画面；监看端作为 USB Host 用 UVC 驱动读取
系统要求拍摄端 Android 14 QPR1+，且厂商在系统中启用 ro.usb.uvc.enabled=true
设备兼容Google Pixel 官方明确支持；小米/华为/OPPO/vivo 等需逐一确认是否启用
画面规格MJPEG / YUYV，最高 1080p 30fps
延迟毫秒级，优于 WiFi

2.3.2 Type-C 下的反向控制

维度结论
UVC 协议本身仅单向传视频，不支持控制指令
可行方案同一 Type-C 线上叠加 ADB 通道（USB 调试），实现触摸控制
复杂度较高：需同时配置 UVC Gadget + ADB，且设备兼容性差
MVP 决策不投入
Type-C 方案结论：传画面可行但设备覆盖率低（需 Android 14+ 且厂商支持 UVC），反向控制需额外叠加 ADB 通道，实现复杂。MVP 不投入，待 WiFi 方案验证后视用户对延迟的反馈再评估。

2.4 美颜方案

方案说明采用
原生相机美颜（屏幕共享方案） 用户在拍摄端原生相机中开启美颜，监看端镜像即可看到美颜效果，无需集成 MVP 采用
GPUPixel（自研备选） 开源 C++/OpenGL 美颜库，支持磨皮、美白、瘦脸、大眼、腮红、口红，跨平台免费。若未来转为自研采集方案可集成 备选
腾讯云 / 火山引擎特效 SDK 功能强大但需付费，且增加包体积 不采用

3. 范围

3.1 P0（MVP 必须实现）

编号能力说明
P0-1双机 WiFi Direct 直连拍摄端开启无线调试，监看端通过配对码连接并建立屏幕镜像
P0-2实时屏幕镜像监看端实时显示拍摄端屏幕，延迟 ≤ 200ms
P0-3触摸控制转发监看端的触摸操作实时转发到拍摄端，可操作原生相机及任意 APP
P0-4方向与旋转自适应监看端画面随拍摄端屏幕方向自动旋转
P0-5连接引导与异常提示引导开启无线调试、断连重连、画面卡顿提示

3.2 P1（后续迭代）

编号能力
P1-1Type-C 有线连接（UVC + ADB，限兼容设备）
P1-2监看端画质/码率调节
P1-3拍摄端息屏继续镜像（降低功耗）
P1-4连接后自动打开拍摄端相机 APP
P1-5快捷键浮窗（一键拍照、切换摄像头）

3.3 明确不做（Excluded）

  • 局域网模式（仅 WiFi Direct 直连）
  • 音频传输
  • 大文件/照片视频回传（拍摄结果仅存拍摄端本地）
  • 跨互联网远程连接
  • iOS 支持
  • 多监看端同时连接（仅 1 对 1）
  • 自研美颜滤镜（复用原生相机）

4. 角色与对象模型

4.1 角色定义

角色设备身份核心能力核心权限
拍摄端（Target） 被镜像与控制的设备，通常架在支架上 提供屏幕画面、执行触摸指令、运行原生相机 需开启「无线调试」；相机、存储权限由原生相机自行管理
监看端（Source） 观看与控制方，由拍摄者手持 接收屏幕画面、转发触摸操作 网络权限；通过 Wireless ADB 连接拍摄端
角色可切换：同一台手机可在不同会话中担任拍摄端或监看端，由用户在连接前选择。

4.2 核心对象：连接会话（Session）

字段说明
role本端角色：target / source
peerDeviceName对端设备名称
state会话状态（见 4.3）
fps / bitrate当前镜像参数

4.3 会话状态机

idle ──发起/配对──> connecting connecting ──ADB 连接成功──> connected connecting ──配对失败/超时──> disconnected connected ──任一端断开──> disconnecting connected ──网络异常──> reconnecting reconnecting ──重连成功──> connected reconnecting ──重连超时(15s)──> disconnected disconnecting ──完成──> idle disconnected ──用户重试──> connecting

5. 核心流程

5.1 首次配对连接流程

[拍摄端] [监看端] │ 选择「作为拍摄端」 │ │ 引导开启「无线调试」 │ │ - 跳转开发者选项 │ │ - 开启无线调试并显示配对码 │ │ │ 选择「作为监看端」 │ │ 输入拍摄端配对码 │ <── Wireless ADB 配对请求 ──────── │ │ 确认配对 │ │ ── 配对成功，建立 ADB 通道 ───────> │ │ 推送 scrcpy server 到拍摄端 │ │ 启动屏幕编码 + 触摸监听 │ │ ── 屏幕视频流 ───────────────────> │ │ │ 解码显示拍摄端屏幕 │ <── 触摸事件 ──────────────────── │ │ 注入触摸事件到系统 │ │ （用户操作原生相机完成拍摄） │

5.2 配对方式

方式操作说明
无线调试配对码（MVP） 拍摄端在「开发者选项 → 无线调试」中查看 IP:端口 和配对码，监看端输入 Android 11+ 原生支持，无需 root
用户体验约束：开启「无线调试」需要用户手动进入开发者选项，操作路径较深。产品需提供清晰的图文引导，并支持自动跳转至对应设置页。配对成功后，后续连接可自动复用，无需再次配对。

5.3 拍摄操作流程

监看端显示拍摄端屏幕 → 用户在拍摄端手动打开原生相机 APP（或 P1 自动打开） → 在监看端屏幕上直接操作： · 点击对焦 · 双指缩放 · 切换前/后摄像头 · 调节美颜（原生相机功能） · 点击快门拍照 / 录像 → 拍摄结果存储在拍摄端本地相册

6. 功能需求

FR-01 角色选择与连接引导

维度说明
触发用户打开 APP
布局首页两个大按钮：「作为拍摄端」「作为监看端」
拍摄端引导 1. 检测是否已开启无线调试
2. 未开启：显示图文引导，提供「跳转开发者选项」按钮
3. 已开启：显示设备的 IP:端口 与配对码，提示等待监看端连接
监看端引导 1. 提示确保两台手机在 WiFi Direct 直连范围内
2. 输入拍摄端的 IP:端口 和配对码
3. 发起连接
结果两端进入 connected 状态
异常 ① 拍摄端系统版本 < Android 11：提示不支持无线调试
② 配对码错误：提示重新输入
③ 连接超时（10s）：提示检查距离与无线调试开关

FR-02 WiFi Direct 直连建立

维度说明
触发用户选择角色后自动发起
处理规则 1. 拍摄端开启 WiFi Direct 监听
2. 监看端扫描并连接拍摄端的 WiFi Direct 热点
3. 连接成功后获取拍摄端 IP，再发起 Wireless ADB 配对
结果两台设备建立点对点网络连接
异常 ① 监看端连接 WiFi Direct 时会断开原有 WiFi，需提前提示用户
② 扫描不到拍摄端：提示检查拍摄端 APP 是否在前台、距离是否过远

FR-03 实时屏幕镜像

维度说明
触发Wireless ADB 连接成功后自动开始
布局监看端全屏显示拍摄端屏幕，顶部显示连接状态、延迟、FPS
处理规则 1. 拍摄端通过 MediaProjection 采集屏幕画面，编码（H.264/H.265）后推送
2. 监看端解码并渲染，目标延迟 ≤ 200ms
3. 画面方向随拍摄端屏幕旋转自适应
4. 延迟 > 500ms 时，监看端顶部黄色提示「网络延迟较高」
结果监看端持续显示拍摄端屏幕
状态streaming / buffering / frozen
异常 ① 画面冻结超过 3s：显示「画面卡顿，正在恢复…」
② 拍摄端锁屏：画面暂停，显示「拍摄端已锁屏」

FR-04 触摸控制转发

维度说明
触发用户在监看端屏幕上触摸、滑动、缩放
处理规则 1. 监看端捕获触摸事件（坐标、手势类型）
2. 通过 ADB 通道转发到拍摄端
3. 拍摄端将触摸事件注入系统（等价于本机触摸）
4. 坐标自动按屏幕分辨率比例映射
结果拍摄端响应触摸操作，如同用户直接操作拍摄端
说明支持点击、滑动、双指缩放；用户可在监看端操作拍摄端的任意 APP，不限于相机
异常触摸事件超时未响应（>500ms）：监看端轻微提示，不阻塞后续操作

FR-05 连接管理与断线重连

维度说明
触发连接成功后网络异常或任一端主动断开
处理规则 1. 心跳检测：每 3s 互发心跳，连续 2 次未收到判定断连
2. 自动重连：断连后自动重试，间隔 2s，最长 15s
3. 重连期间监看端保持最后一帧画面并显示「重连中…」
4. 已配对设备无需重新输入配对码
结果重连成功恢复镜像；超时进入 disconnected
异常拍摄端主动断开时，监看端显示「拍摄端已结束连接」，不自动重连

FR-06 设备状态监控

维度说明
触发连接成功后持续上报
处理规则拍摄端每 10s 上报电量与屏幕状态；监看端顶栏显示对端电量
异常拍摄端电量 ≤ 10% 时，监看端红色提示「拍摄端电量低，请及时充电」

7. 共享规则与异常

7.1 权限矩阵

权限拍摄端监看端说明
无线调试必须开启不需要用于建立 ADB 通道
网络必须必须WiFi Direct 点对点传输
前台服务必须必须保持连接不被系统杀死
摄像头原生相机自管不需要本 APP 不直接调用摄像头
存储不需要不需要拍摄结果由原生相机存入系统相册

7.2 数据边界

  • 屏幕画面与触摸指令仅在两台设备间本地传输，不上传任何云端服务器。
  • 不传音频，不传大文件。照片/视频仅存储在拍摄端本地相册。
  • 连接断开后，监看端不保留任何拍摄端画面数据。

7.3 核心异常处理汇总

场景拍摄端表现监看端表现恢复方式
网络断连显示「连接断开」重连遮罩，自动重连 15s自动重连或手动重连
拍摄端被来电打断屏幕显示来电界面镜像来电界面，操作暂停通话结束自动恢复
拍摄端锁屏屏幕熄灭显示「拍摄端已锁屏」用户点亮拍摄端屏幕
监看端切后台继续推流停止接收回前台自动恢复
无线调试被关闭提示重新开启连接断开重新开启并配对

8. 开放问题

编号问题影响建议
Q1 用户开启「无线调试」的门槛较高，是否接受？ 影响首次配对成功率 提供详细图文引导 + 自动跳转设置页；评估是否可通过 Shizuku 等方案降低门槛
Q2 屏幕镜像延迟是否满足自拍实时取景需求？ 影响核心体验 WiFi Direct 下目标 ≤ 200ms，需实测验证；不满足则考虑降分辨率/码率
Q3 是否需要连接后自动打开拍摄端原生相机？ 影响操作便捷性 列入 P1，通过 ADB 命令 am start 拉起相机
Q4 Type-C 有线方案是否值得投入？ 需额外开发且设备兼容差 视 WiFi 方案延迟满意度决定；若用户对延迟敏感且持有 Pixel 等兼容设备，可考虑 P1
